# Турниры креаторов и Pick'em

Night Core содержит опциональную систему Creator Major: single-elimination турниры креаторов, уровни на каждый матч, прогнозы игроков, Pick'em-очки, награды, таблицу лидеров и веб-интерфейс в стиле вкладок Geometry Dash.

Система отделена от штатного протокола GD. Если она выключена, Night Core продолжает работать как обычный GDPS 2.2, а турнирная история остаётся в БД.

## Режимы

```env
TOURNAMENTS_MODE=enabled
TOURNAMENT_PREDICTIONS_MODE=enabled
```

Оба параметра принимают:

- `enabled` — чтение и запись разрешены;
- `read_only` — история доступна, новые изменения/прогнозы запрещены;
- `disabled` — функция скрыта и недоступна вызывающему коду.

Смена режима не удаляет строки из турнирных таблиц. Уже заработанную награду можно забрать и в `read_only`.

## Хранение

`0023_creator_tournaments.sql` создаёт отдельные таблицы турниров, участников, матчей и прогнозов.

`0024_creator_tournament_brackets.sql` добавляет:

- описание и правила Major;
- формат и размер сетки;
- номер/размер раунда;
- связь матча со следующим матчем и слотом;
- отдельный audit trail действий персонала.

Турнирные данные не смешиваются с обычным прогрессом аккаунта и не обязательны для работы базового сервера.

## Сетка

Поддерживаются размеры `4`, `8`, `16`, `32` участников.

Сетка строится автоматически по seed. После фиксации победителя Night Core:

1. закрывает текущий матч;
2. рассчитывает прогнозы на этот матч;
3. отмечает проигравшего как выбывшего;
4. переносит победителя в правильный слот следующего раунда;
5. после финала объявляет чемпиона;
6. рассчитывает прогнозы на чемпиона и итоговый Pick'em.

Повторно генерировать сетку поверх существующих матчей нельзя.

## Матчи

Для каждого матча персонал назначает два ID уровней — по одному уровню от каждого участника. Перед открытием матча оба участника и оба уровня должны существовать.

Состояния матча:

`scheduled -> open -> judging -> completed`

Во время `open` игроки могут менять свой прогноз до `locksAt`. После завершения результат Pick'em фиксируется.

## Pick'em

Игрок может:

- выбрать чемпиона всего Major;
- выбрать победителя каждого открытого матча;
- менять выбор до блокировки;
- получать Pick'em-очки за правильные ответы;
- видеть свои результаты и общий leaderboard;
- один раз забрать сохранённую награду за правильный прогноз.

Награда хранится JSON-снимком, например:

```json
{"badge":"major-2026-champion-pick","seasonXp":250}
```

Турнирный модуль намеренно не меняет XP/бейджи других будущих систем напрямую. Это позволяет оставить Tournaments независимым модулем и позже подключить единый reward adapter.

## Веб-интерфейс

Публичная страница:

```text
/tournaments.php
```

Вкладки:

- Overview — состояние, даты, правила и участники;
- Bracket — вся сетка и прогнозы на открытые матчи;
- Pick'em — прогноз на чемпиона и личная история прогнозов;
- Leaderboard — рейтинг прогнозистов;
- Rewards — доступные награды;
- Admin — управление Major для персонала.

Страница использует отдельный CSS `public/assets/tournaments.css`: визуал вдохновлён обычными GD-меню (синие заголовки, объёмные кнопки, коричневые панели), без копирования игровых ассетов.

Игрок входит тем же аккаунтом GDPS. POST-действия защищены существующим `PanelSecurity` и CSRF.

## Публичный API

Для будущего Geode/клиентского интерфейса есть read-only endpoint:

```text
/tournamentApi.php
/tournamentApi.php?id=123
```

Без `id` возвращается список Major. С `id` — турнир, участники, матчи и, если прогнозы не отключены, Pick'em leaderboard.

## Права персонала

- `tournaments.manage` — создавать Major, добавлять участников, строить сетку, назначать уровни и менять стадии;
- `tournaments.resolve` — фиксировать победителей.

Bootstrap-owner получает эти права через существующий staff access.

## Backend API

Старый минимальный интерфейс сохранён для совместимости:

```php
$service = TournamentModule::boot($app->db(), $app->tables(), $app->staffAccess());
```

Для полной системы используется:

```php
$system = TournamentModule::bootSystem($app->db(), $app->tables(), $app->staffAccess());
$system->competition();
$system->view();
$system->core();
```

Новые операции конфигурируются небольшими объектами `TournamentSetup`, `BracketSettings` и `MatchEntries`, чтобы UI и сервисы не передавали длинные списки параметров.

## Проверка

Отдельный GitHub Actions workflow `Tournament system` проверяет:

1. PHP-синтаксис турнирного backend, web-контроллера, public endpoints и тестов;
2. режимы `enabled/read_only/disabled`;
3. алгоритм seed/раундов;
4. полный 8-креаторский Major на MariaDB;
5. автопродвижение победителей до финала;
6. Pick'em и одноразовую награду;
7. HTTP-запуск `/tournaments.php`;
8. JSON-ответ `/tournamentApi.php`;
9. отсутствие Fatal/Parse/Uncaught ошибок в server log.

Geode-вкладка и адаптер реальной выдачи наград в другие опциональные системы остаются отдельными интеграционными слоями; текущий Creator Major уже полностью управляется через веб-интерфейс.
